1. Какая команда оказалась самой непонятной до практики?
Из за особенностей работы с множеством веток, самая непонятная для меня команда - cherry-pick (альтернатива commit).
Позволяет формировать новые коммиты, выбирая несколько предыдущих коммитов за основу, также может
использоваться в разрешении конфликтов. 

2. Почему важно настраивать user.name/email перед коммитами?
Для идентефикации неавторизованных контрибьюторов проекта.

3. В каком случае git revert безопаснее, чем git reset?
Всегда? git reset переписывает историю и если был хоть один коммит в удалённый репозиторий,
то использование git reset приведёт к хаосу у участников ветки.
Единственное применение git reset - если коммит ещё не был выполнен и необходимо откатиться
на актуальное состояние ветки, при этом потеряв все локальные изменения.

4. Как .gitignore мог бы спасти проект от утечки данных?
Для этого нужно исключать из проекта файлы, содержащие в себе API-ключи
или прочую чувствительную информацию (ex: данные пользователей)
Переодически такое всёравно происходит по вине невнимательных контрибьюторов
